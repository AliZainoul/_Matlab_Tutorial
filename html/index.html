1. Introduction aux GUI/IHM avec MATLAB

Concept Fondamental: Interface Graphique Utilisateur (GUI/IHM)

Une GUI (Graphical User Interface) ou IHM (Interface Homme-Machine) est un système qui permet l'interaction entre l'utilisateur et le programme à travers des éléments visuels interactifs plutôt que des lignes de commande.

MATLAB App Designer utilise une approche orientée objet pour créer des interfaces graphiques. Notre calculatrice illustre tous les concepts clés d'une application GUI moderne.

% Structure de base d'une application MATLAB classdef calculator_exported < matlab.apps.AppBase % Héritage de la classe AppBase fournie par MATLAB % Cela donne accès aux fonctionnalités de base des GUI end
Point Clé: L'héritage de matlab.apps.AppBase fournit l'infrastructure nécessaire pour gérer le cycle de vie de l'application, l'enregistrement des composants, et la communication avec MATLAB.

2. Architecture MVC et Programmation Orientée Objet

Concept: Modèle-Vue-Contrôleur (MVC)

Le pattern MVC sépare l'application en trois composants interconnectés:

  • Modèle: Les données et la logique métier
  • Vue: L'interface utilisateur visuelle
  • Contrôleur: La logique qui gère les interactions

2.1 Organisation des Propriétés

% VUE: Composants visuels (public pour App Designer) properties (Access = public) UIFigure matlab.ui.Figure ResultTextArea matlab.ui.control.TextArea PlusButton matlab.ui.control.Button % ... autres composants visuels end % MODÈLE: État interne de l'application (private) properties (Access = private) UseLegacyTextArea (1,1) logical = false end % CONFIGURATION: Constantes immuables properties (Constant, Access = private) BUTTON_LAYOUT = {'C','Delete','(',')'; ...} LEGACY_YEAR_THRESHOLD = 2019 end
Principe d'Encapsulation: Les propriétés publiques exposent la vue, les propriétés privées cachent l'implémentation, et les constantes définissent la configuration immuable.

3. Gestion des Composants Visuels

Concept: Hiérarchie de Composants

Les GUI sont construites comme une hiérarchie d'objets visuels, chaque composant ayant un parent. Cette structure arborescente facilite la gestion et le positionnement.

3.1 Création de la Fenêtre Principale

function createFigure(app) % UIFigure = conteneur racine de l'application app.UIFigure = uifigure('Visible', 'off'); app.UIFigure.Position = [100, 100, 640, 480]; app.UIFigure.Name = 'Calculator'; % Masquer la fenêtre pendant la construction % Améliore l'expérience utilisateur (pas de "flash") end
Exemple Pratique: La propriété Visible = 'off' pendant la construction évite que l'utilisateur voie les composants se positionner un par un. Une fois tout construit, on affiche la fenêtre complète.

3.2 Types de Composants GUI

Type Classe MATLAB Usage dans la Calculatrice

4. Systèmes de Layout et Positionnement

Concept: Gestionnaires de Layout

Un layout manager contrôle automatiquement la position et la taille des composants enfants selon des règles définies. Cela rend l'interface responsive et maintenable.

4.1 GridLayout - Organisation en Grille

% Création d'une grille 6×4 app.GridLayout = uigridlayout(app.UIFigure); app.GridLayout.ColumnWidth = {'1x','1x','1x','1x'}; app.GridLayout.RowHeight = {'1x','1x','1x','1x','1x','1x'}; % Placement d'un composant dans la grille app.ResultTextArea.Layout.Row = 1; app.ResultTextArea.Layout.Column = [2, 4]; % Span sur 3 colonnes
Avantages du GridLayout:
  • Redimensionnement automatique des composants
  • Alignement cohérent sans calculs manuels
  • Support du spanning (fusion de cellules)
  • Adaptation aux différentes tailles d'écran

4.2 Création Dynamique de Composants

% Principe DRY: Ne pas répéter le code function createButtons(app) [nRows, nCols] = size(app.BUTTON_LAYOUT); btnHandles = cell(nRows, nCols); % Boucle pour créer tous les boutons for r = 1:nRows for c = 1:nCols btn = uibutton(app.GridLayout, 'push'); btn.Text = app.BUTTON_LAYOUT{r, c}; btn.Layout.Row = r + 1; btn.Layout.Column = c; btnHandles{r, c} = btn; end end end
Avantage: Pour modifier la disposition des boutons, il suffit de changer la matrice BUTTON_LAYOUT. Le code de création reste inchangé - c'est le principe de séparation des données et de la logique.

5. Gestion des Événements (Event-Driven Programming)

Concept: Programmation Événementielle

Dans une GUI, le flux d'exécution est déterminé par les actions de l'utilisateur (clics, saisies, etc.). Le programme attend des événements et réagit via des callbacks.

5.1 Structure d'un Callback

% ENREGISTREMENT du callback (dans startupFcn) app.PlusButton.ButtonPushedFcn = @(~,~) app.operatorButtonPushed('+'); │ │ │ │ │ │ │ └─ Méthode appelée │ │ └─ Fonction anonyme │ └─ Propriété événement └─ Composant source % DÉFINITION du callback (méthode) function operatorButtonPushed(app, op) app.append(op); % Action à effectuer end
Pattern Observer: Le composant (Subject) notifie l'application (Observer) quand un événement se produit. Ce découplage permet de changer facilement le comportement sans modifier le composant.

5.2 Organisation des Callbacks par Catégorie

function startupFcn(app) % Groupement logique des callbacks app.registerDigitCallbacks(); app.registerOperatorCallbacks(); app.registerParenthesisCallbacks(); app.registerUtilityCallbacks(); end function registerDigitCallbacks(app) % Structure de données pour éviter la répétition digitButtons = { app.ZeroButton, '0'; app.OneButton, '1'; app.TwoButton, '2'; % ... }; % Boucle d'enregistrement for i = 1:size(digitButtons, 1) btn = digitButtons{i, 1}; val = digitButtons{i, 2}; btn.ButtonPushedFcn = @(~,~) app.digitButtonPushed(val); end end
Maintenabilité: Cette approche modulaire facilite l'ajout de nouveaux boutons ou la modification des comportements existants sans toucher au reste du code.

6. Compatibilité Cross-Version

Concept: Abstraction des Différences de Version

Les API évoluent entre versions. Une bonne pratique consiste à détecter les différences et à créer une couche d'abstraction pour maintenir la compatibilité.

6.1 Détection de Version

function detectVersion(app) % Récupération des informations de version v = ver('MATLAB'); year = str2double(v.Date(end-3:end)); % Flag pour adapter le comportement app.UseLegacyTextArea = (year <= app.LEGACY_YEAR_THRESHOLD); end

6.2 Couche d'Abstraction

% API unifiée indépendante de la version function txt = getText(app) if app.UseLegacyTextArea % R2019-: Value est un cell array if isempty(app.ResultTextArea.Value) txt = ""; else txt = string(app.ResultTextArea.Value{1}); end else % R2020+: Value est un string txt = string(app.ResultTextArea.Value); end end function setText(app, txt) if app.UseLegacyTextArea app.ResultTextArea.Value = {char(txt)}; else app.ResultTextArea.Value = txt; end end
Principe d'Isolation: Le reste du code appelle uniquement getText() et setText(), sans se soucier de la version de MATLAB. La complexité est isolée dans ces deux méthodes.

7. Patterns de Conception GUI

7.1 Pattern: Séparation de la Logique Métier

% MAUVAISE pratique: logique métier dans le callback function equalsButtonPushed_BAD(app) expr = app.getText(); expr = replace(expr, "x", "*"); expr = replace(expr, "÷", "/"); try result = eval(expr); app.setText(num2str(result)); catch app.setText("Error"); end end % BONNE pratique: séparation claire function equalsButtonPushed(app) app.evaluateExpression(); % Callback minimal end function evaluateExpression(app) % Logique métier isolée et testable expr = app.getText(); expr = app.normalizeExpression(expr); try result = eval(expr); app.setText(num2str(result)); catch ME app.setText("Error"); warning('Calculator:EvaluationError', ... 'Failed: %s', ME.message); end end

7.2 Pattern: Validation et Normalisation

function normalizedExpr = normalizeExpression(~, expr) % Transformation des symboles d'affichage % vers des opérateurs MATLAB valides operatorMappings = { 'x', '*'; '÷', '/' }; normalizedExpr = expr; for i = 1:size(operatorMappings, 1) displayOp = operatorMappings{i, 1}; matlabOp = operatorMappings{i, 2}; normalizedExpr = replace(normalizedExpr, displayOp, matlabOp); end end
Extensibilité: Pour ajouter de nouveaux opérateurs (puissance, racine, etc.), il suffit d'ajouter une ligne dans operatorMappings et de créer le bouton correspondant.

7.3 Pattern: Gestion d'Erreurs Robuste

try result = eval(expr); app.setText(num2str(result)); catch ME % Feedback utilisateur app.setText("Error"); % Logging pour le développeur warning('Calculator:EvaluationError', ... 'Failed to evaluate: %s\nReason: %s', ... expr, ME.message); end
Double Niveau de Gestion:
  • Message simple pour l'utilisateur final ("Error")
  • Détails techniques dans les logs pour le débogage

    val = digitButtons{i, 2};

end

8.3 Optimisation des Performances

Stratégies d'Optimisation GUI
  • Construction Invisible: Créer tous les composants avec Visible='off', puis afficher en une fois
  • Pré-allocation: Utiliser des cell arrays pour stocker les handles de boutons
  • Validation des Types: Utiliser (1,1) logical pour les propriétés scalaires
  • Constants: Définir les valeurs de configuration comme Constant pour éviter les modifications accidentelles

8.4 Architecture Modulaire

% Construction hiérarchique et modulaire function createComponents(app) app.createFigure(); % Conteneur principal app.createDisplayArea(); % Zone d'affichage app.createButtons(); % Boutons interactifs app.UIFigure.Visible = 'on'; % Révélation finale end
Avantages de la Modularité:
  • Code facile à lire et à maintenir
  • Tests unitaires possibles sur chaque module
  • Réutilisation des composants dans d'autres projets
  • Débuggage simplifié (isolation des problèmes)

9. Cycle de Vie d'une Application GUI

Concept: Cycle de Vie

Une application GUI traverse plusieurs phases depuis sa création jusqu'à sa destruction. Comprendre ce cycle est essentiel pour une gestion correcte des ressources.

% 1. CONSTRUCTION function app = calculator_exported() detectVersion(app); % Initialisation de l'état createComponents(app); % Création de la vue registerApp(app, app.UIFigure); % Enregistrement MATLAB startupFcn(app); % Configuration des callbacks if nargout == 0 clear app; % Mode autonome (pas de variable) end end % 2. EXÉCUTION (boucle événementielle MATLAB) % L'application attend les événements utilisateur % 3. DESTRUCTION function delete(app) delete(app.UIFigure); % Nettoyage des ressources end

10. Exercices Pratiques

Exercice 1: Ajouter un Bouton Racine Carrée

Objectif: Étendre la calculatrice avec une fonction racine carrée (√).

Étapes:

  1. Modifier BUTTON_LAYOUT pour inclure '√'
  2. Créer SqrtButton dans les propriétés
  3. Assigner le handle dans assignButtonHandles()
  4. Ajouter le mapping 'sqrt' dans normalizeExpression()
  5. Enregistrer le callback dans registerOperatorCallbacks()

Exercice 2: Historique des Calculs

Objectif: Sauvegarder les 5 derniers calculs effectués.

Concepts à utiliser:

  • Nouvelle propriété CalculationHistory (cell array)
  • Composant ListBox pour afficher l'historique
  • Méthode addToHistory() pour gérer la liste
  • Callback de sélection pour recharger un calcul

Exercice 3: Validation d'Expression

Objectif: Empêcher l'évaluation d'expressions invalides.

Points à implémenter:

  • Vérifier l'équilibre des parenthèses
  • Détecter les opérateurs consécutifs (ex: "5++3")
  • Valider les points décimaux (un seul par nombre)
  • Désactiver le bouton "=" si l'expression est invalide

11. Concepts Avancés

11.1 Pattern: State Management

Gestion d'État Centralisée

Pour des applications complexes, centraliser l'état dans une structure dédiée facilite le débogage et la maintenance.

% Structure d'état centralisée properties (Access = private) AppState struct = struct(... 'CurrentExpression', '', ... 'LastResult', [], ... 'ErrorState', false, ... 'CalculationHistory', {{}} ... ) end % Méthodes de mise à jour d'état function updateState(app, field, value) app.AppState.(field) = value; app.refreshUI(); % Synchroniser la vue end function refreshUI(app) % Mettre à jour tous les composants selon l'état app.setText(app.AppState.CurrentExpression); if app.AppState.ErrorState app.ResultTextArea.FontColor = 'red'; else app.ResultTextArea.FontColor = 'black'; end end

11.2 Pattern: Command Pattern pour Undo/Redo

% Définition d'une commande classdef CalculatorCommand properties Type % 'append', 'delete', 'clear', 'evaluate' Data % Données associées PreviousState end methods function execute(cmd, app) % Exécuter la commande cmd.PreviousState = app.getText(); switch cmd.Type case 'append' app.append(cmd.Data); case 'delete' app.deleteButtonPushed(); % ... end end function undo(cmd, app) % Annuler la commande app.setText(cmd.PreviousState); end end end

11.3 Callbacks Asynchrones

% Opérations longues sans bloquer l'UI function complexCalculationButtonPushed(app) % Désactiver les boutons pendant le calcul app.enableButtons(false); app.setText("Calcul en cours..."); % Calcul asynchrone afterEach(parfeval(@app.performComplexCalculation, 1, expr), ... @(result) app.onCalculationComplete(result)); end function onCalculationComplete(app, result) app.setText(num2str(result)); app.enableButtons(true); end
